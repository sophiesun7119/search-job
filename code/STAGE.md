# Implementation stage

This file tracks **verified progress and next gates**. The target workflow and public filter rules live in [PLAN.md](PLAN.md); the code entry point and commands live in [README.md](README.md). Update this file when a stage passes or its scope changes. A planned step below is not a claim that it currently runs.

| Stage | State | Evidence and next gate |
| --- | --- | --- |
| 0. Public repository scaffold | Complete | Separate `search-job/` repository, `dev` workflow and documented target. |
| 1. Data and output contract | Complete | SQLite schema, opening identity/variants, title categories, age/open-state rules, deterministic README/JSON renderer and focused tests exist. The current local live DB contains 118 company records. |
| 2. Collector extraction | Twelve active; two planned | Greenhouse, Ashby, SmartRecruiters, Gem, Rippling, ViziRecruiter, Eightfold, Lever, Workday, Workable, JazzHR and Oracle have tested readers. iCIMS and CareerPuck remain adapter-pending. Honeywell's Oracle API consistently reports one more job than its publicly visible requisitions; two independent sort orders returned the same 1,298 visible IDs, and the one-count discrepancy is reported with the scan. JazzHR's tested board does not expose a source publication date, so its raw jobs stay in SQLite but cannot enter the 72-hour README. Eightfold pagination can be partial when the source repeats IDs. |
| 3. Company intake and routes | Partial | Bounded, resumable Simplify catalog import stores third-party leads separately from verified companies. `--triage-leads` checks saved sample Apply URLs and redirects before resolving candidate company domains and testing official careers pages for ATS links. A company is registered only after official route evidence and a tested adapter. In the first 100-lead batch, 40 routes completed scans; 55 are route-pending, two board-pending and three adapter-pending. A local generated review Dashboard lists all 60 unfinished leads, their source and current links, script blocker and AI review state. None has been marked `needs_user` without a recorded AI attempt. The original catalog `canonical_domain` is empty for these 100, while 99 company websites were preserved from their Simplify profiles. Method attribution is stored for new routes; older rows are left unattributed unless their evidence chain is recoverable. Clearwater's rebranded `cwan.com` site was AI-verified through its official Workday feed after the script missed its embedded route. Color Health's official careers page now links CareerPuck rather than the Ashby route in Simplify's saved sample. Some official pages reject automated requests or require JavaScript, and the importer does not solve those routes by itself. |
| 4. Bounded live search loop | Existing pool and 40 new boards scanned on dev | The original 78-company pool had 75 complete boards, with three identity/board holds. The first Simplify batch added 40 fully scanned company boards across Ashby, Greenhouse, Lever, Workday, Workable, JazzHR and Oracle, with no scan failure in that completed subset. README generation applies latest-complete-scan, age and confirmed-US-location rules; older, non-US, date-unknown and inactive jobs stay in SQLite and local JSON. |
| 5. Local refresh and release | Incremental window rule implemented; scheduling planned | New companies admit a 72-hour publication window and become old after one complete successful scan; old companies admit new postings from 24 hours while refreshing saved postings still visible in the 72-hour README. APIs without server-side date filtering still fetch complete listings for status checks. No automatic schedule, GitHub Actions or unattended AI task is implemented. |

**Current limit:** the root README is a saved live-index projection, not a guarantee that every application link is still open at viewing time. The first Simplify batch is incomplete: unresolved leads remain explicitly staged for official route, board or adapter work. No unattended AI handoff or schedule runs in this repository. The agent skills describe conditional AI handoffs, while routine existing-board scans are script-run.
