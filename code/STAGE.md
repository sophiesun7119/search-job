# Implementation stage

This file tracks **verified progress and next gates**. The target workflow and public filter rules live in [PLAN.md](PLAN.md); the code entry point and commands live in [README.md](README.md). Update this file when a stage passes or its scope changes. A planned step below is not a claim that it currently runs.

| Stage | State | Evidence and next gate |
| --- | --- | --- |
| 0. Public repository scaffold | Complete | Separate `search-job/` repository, `dev` workflow and documented target. |
| 1. Data and output contract | Complete | SQLite schema, opening identity/variants, title categories, age/open-state rules, deterministic README/JSON renderer and focused tests exist. The current local live DB contains 111 company records and 18,700 deduplicated opening identities. |
| 2. Collector extraction | Eleven active; two planned | Greenhouse, Ashby, SmartRecruiters, Gem, Rippling, ViziRecruiter, Eightfold, Lever, Workday, Workable and JazzHR have tested readers. Oracle and iCIMS remain adapter-pending. JazzHR's tested board does not expose a source publication date, so its raw jobs stay in SQLite but cannot enter the 72-hour README. Eightfold pagination can be partial when the source repeats IDs. |
| 3. Company intake and routes | Partial | Bounded, resumable Simplify catalog import stores third-party leads separately from verified companies. The script extracts candidate official domains from public Simplify profiles and tests official company careers pages for ATS links. A company is registered only after official route evidence and a tested adapter. In the first 100-lead batch, 33 routes completed scans; 63 are route-pending, two board-pending and two adapter-pending. Some official pages reject automated requests or require JavaScript, and the importer does not solve those routes by itself. |
| 4. Bounded live search loop | Existing pool and 33 new boards scanned on dev | The original 78-company pool had 75 complete boards, with three identity/board holds. The first Simplify batch added 33 fully scanned company boards across Ashby, Greenhouse, Lever, Workday, Workable and JazzHR, with no scan failure in that completed subset. README generation applies latest-complete-scan, age and confirmed-US-location rules; older, non-US, date-unknown and inactive jobs stay in SQLite and local JSON. |
| 5. Local refresh and release | Incremental window rule implemented; scheduling planned | New companies admit a 72-hour publication window and become old after one complete successful scan; old companies admit new postings from 24 hours while refreshing saved postings still visible in the 72-hour README. APIs without server-side date filtering still fetch complete listings for status checks. No automatic schedule, GitHub Actions or unattended AI task is implemented. |

**Current limit:** the root README is a saved live-index projection, not a guarantee that every application link is still open at viewing time. The first Simplify batch is incomplete: unresolved leads remain explicitly staged for official route, board or adapter work. No unattended AI handoff or schedule runs in this repository. The agent skills describe conditional AI handoffs, while routine existing-board scans are script-run.
