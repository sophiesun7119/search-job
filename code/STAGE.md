# Implementation stage

This file tracks **verified progress and next gates**. The target workflow and public filter rules live in [PLAN.md](PLAN.md); the code entry point and commands live in [README.md](README.md). Update this file when a stage passes or its scope changes. A planned step below is not a claim that it currently runs.

| Stage | State | Evidence and next gate |
| --- | --- | --- |
| 0. Public repository scaffold | Complete | Separate `search-job/` repository, `dev` workflow and documented target. |
| 1. Data and output contract | Complete for local fixtures and historical preview | SQLite schema, opening identity/variants, title categories, age/open-state rules, deterministic README/JSON renderer and focused tests exist. A read-only old-cache projection produced the labeled root README from 78 known companies: 50 have 797 saved ATS postings; one custom-careers row lacked a verified board and was excluded. All preview postings have **unknown** current open state. The independent production DB starts with an empty openings table. |
| 2. Collector extraction | Complete for seven providers with active routes; two future providers remain | Greenhouse, Ashby, SmartRecruiters, Gem, Rippling, ViziRecruiter and Eightfold readers run without personal filters. Lever and Workday readers have not been extracted because the current pool has no registered routes for them. Eightfold pagination can be partial when the source repeats IDs. |
| 3. Company intake and routes | Partial | Portable route-seed import and identity-review hold are implemented. Three lead entrances and fresh official ATS discovery are still planned. A successful board listing recheck does not replace a separate official company-to-board ownership check where that identity is disputed. |
| 4. Bounded live search loop | Final existing-pool recheck complete on dev | The 78-company pool was rechecked one provider at a time: 75 registered boards returned complete listings, including CACI Eightfold. SQLite holds 14,178 deduplicated identities with refreshed location/link variants. All 75 successfully checked companies are `old`; Brex and WhatNot lack a registered board, and General Dynamics UK remains on identity hold, so those three remain `new`. The root README is a generated past-72-hour US-location view; older, non-US, date-unknown and inactive jobs stay in SQLite and local JSON. |
| 5. Local refresh and release | Incremental window rule implemented; scheduling planned | New companies admit a 72-hour publication window and become old after one complete successful scan; old companies admit new postings from 24 hours while refreshing saved postings still visible in the 72-hour README. APIs without server-side date filtering still fetch complete listings for status checks. No automatic schedule, GitHub Actions or unattended AI task is implemented. |

**Current limit:** the root README is a saved live-index projection, not a guarantee that every application link is still open at viewing time. The current scan reuses a local route seed; no fresh company discovery, official ownership audit for every route, unattended AI handoff or schedule has run in this repository. The agent skills describe four conditional AI handoffs, while routine existing-board scans are script-run.
