# Implementation stage

This file tracks **verified progress and next gates**. The target workflow and public filter rules live in [PLAN.md](PLAN.md); commands live in [README.md](README.md). A planned step is not a claim that it runs today.

| Stage | State | Evidence and next gate |
| --- | --- | --- |
| 0. Public repository scaffold | Complete | Separate `search-job/` repository, `dev` workflow and documented target. |
| 1. Data and output contract | Complete | SQLite schema, opening identity and variants, title categories, age and open-state rules, deterministic README/JSON renderer, and focused tests. The current local DB has 146 company records. |
| 2. Collector extraction | Sixteen active | Greenhouse, Ashby, SmartRecruiters, Gem, Rippling, ViziRecruiter, Eightfold, Lever, Workday, Workable, JazzHR, Oracle, CareerPuck, iCIMS, Pinpoint, and BambooHR have tested readers. iCIMS supports classic and company-domain Jibe listings. Pinpoint uses its public postings feed and detail-page `datePosted`; BambooHR uses its public careers list and detail `datePosted`. Eightfold accepts an officially linked company-domain board and uses standardized locations when available. JazzHR does not expose a source publication date, so its date-unknown jobs cannot enter the 72-hour README. Oracle and Eightfold may report a source count gap or partial pagination; the scanner records these rather than asserting completion. |
| 3. Company intake and routes | Partial | The bounded Simplify import keeps third-party leads separate from verified companies. The script probes saved sample Apply URLs before checking official company pages. AI investigates unresolved routes and builds adapters. Of the first 100 leads, 68 completed scans and 32 remain route-pending. The local review Dashboard lists source links, blockers, and review state for every pending lead. Some old sample URLs point to a different board from the current official careers page; those routes require fresh attribution. |
| 4. Bounded live search loop | Existing pool and 68 new boards scanned on `dev` | The original 78-company pool had 75 complete boards, with three identity/board holds. README generation applies latest-complete-scan, age, and confirmed-US-location rules. The local DB retains previously indexed older, non-US, date-unknown, and inactive openings. |
| 5. Local refresh and release | Incremental window rule implemented; scheduling planned | New companies admit a 72-hour publication window and become old after one complete successful scan. Old companies admit new postings from 24 hours while refreshing saved postings still visible in the 72-hour README. APIs without server-side date filtering fetch complete listings for status checks. No automatic schedule, GitHub Actions, or unattended AI task is implemented. |

**Current limit:** The root README is a saved live-index projection, not a guarantee that every application link remains open at viewing time. The first Simplify batch remains incomplete, and unresolved leads stay explicitly staged. The agent skills describe conditional AI handoffs; routine existing-board scans are script-run.
